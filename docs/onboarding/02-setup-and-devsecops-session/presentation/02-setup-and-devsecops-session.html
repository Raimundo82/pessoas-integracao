Git Hooks — Lefthook

CONCEPT

Hooks run automatically at specific Git events — before code ever reaches Gitea.

lefthook.yml — pre-commit hook

pre-commit: parallel: true commands: prettier: stage_fixed: true glob: '**/*.{md,yml,yaml,json,jsonc}' run: npx prettier --write {staged_files} dotnet-format: stage_fixed: true glob: '**/*.cs' run: dotnet format --include {staged_files}

What happens on git commit

⌨
git commit -m "..."
⚡
Lefthook: pre-commit
✎
prettier → fix .md/.yml/.json → re-stage
✎
dotnet format → fix .cs → re-stage
✓
Commit created (already formatted)
stage_fixed: true — Lefthook re-stages the fixed file automatically. You never get an "unstaged fixes" situation.

The Linter — dotnet format & Prettier

CONCEPT

dotnet format — C# files

Reads rules from .editorconfig — indent size, spacing, blank lines, Roslyn analyser settings.

# Fix all violations dotnet format # Verify only (what CI runs) dotnet format --verify-no-changes # Single file (what the hook does) dotnet format --include path/to/File.cs

Prettier — md / yml / json

Enforces consistent formatting for non-C# files. Config in .prettierrc. Strict — it rewrites to its own opinion.

# Fix all files npx prettier --write . # Check only (CI mode) npx prettier --check . # Single file npx prettier --check file.yaml

✅ Fix mode — use locally

dotnet format — rewrites files to match .editorconfig. Run before committing, or let the hook do it.

⚠️ Verify mode — what CI runs

dotnet format --verify-no-changes — exit code 1 if anything would change. No files are modified. If this fails, CI fails.

CI Phases — ci-build-test

CONCEPT

Runs on every PR — all phases must pass before a PR can be merged.

①
Checkout (fetch-depth: 0)
Full Git history — needed by SonarQube and semantic-release
②
Setup Node.js 24.10.x + npm ci
Installs Lefthook, Prettier, semantic-release
③
Setup .NET SDK (from global.json)
Pins to 10.0.201 — same as dev container
④
dotnet format --verify-no-changes
FAILS FAST — no compile needed. Catches unformatted code in seconds.
⑤
dotnet build --no-incremental
Clean build — no cached artifacts, catches compile errors
⑥
dotnet list package --vulnerable
NuGet CVE check — reads package lock, no network call
⑦
dotnet test --no-build
Runs all tests — --no-build skips recompile (already done in ⑤)

Why this order?

Cheapest to most expensive. Format fails in 5s — you never wait 2min for tests to tell you what a linter could. Each phase only runs if the previous one passed.

global.json pins the SDK

{ "sdk": { "version": "10.0.201" } }
setup-dotnet reads this — same version in CI and dev container. No "works locally but not in CI".

Run CI locally before pushing

dotnet format --verify-no-changes
dotnet build --no-incremental
dotnet list package --vulnerable
dotnet test --no-build

SonarQube Scan

CONCEPT

Static analysis — catches bugs, code smells and security issues that the compiler misses.

Two workflows, two purposes

ci-pr-scanEvery PR — analyses only NEW code. Result decorated on the PR itself.
post-merge-scanPush to master — full analysis of the entire codebase.

PR scan — what happens

1
dotnet-sonarscanner begin
Opens a SonarQube analysis session
2
dotnet build
Compiles with Sonar instrumentation
3
dotnet-coverage collect "dotnet test"
Runs tests, captures coverage.xml
4
dotnet-sonarscanner end
Uploads results to the SonarQube server
5
Quality Gate check
Polls SonarQube — PR cannot merge if gate not met

Quality Gate

Conditions set on the server: coverage on new code ≥ X% · no new bugs · no unreviewed security hotspots. PR cannot be merged if the Quality Gate fails.

What SonarQube analyses

  • Bugs — null dereferences, resource leaks
  • Code smells — long methods, dead code
  • Security hotspots — hardcoded credentials, SQL injection risk
  • Coverage — which lines are tested

Excluded from scan

Migrations/ · bin/ · obj/ · Generated/ · .devcontainer/
EF Core migrations are auto-generated — no benefit from static analysis.

SonarLint in VS Code

Same rules as the CI scan — inline feedback as you type. Connect to the server with your SONARQUBE_USER_TOKEN for connected mode.
