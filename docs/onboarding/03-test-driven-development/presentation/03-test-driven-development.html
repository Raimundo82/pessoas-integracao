TDD — Red → Green → Refactor

CONCEPT
🔴 RED
Write a failing test first. The test defines the behaviour you want. Run it — if it passes, the test is wrong.
→
🟢 GREEN
Write the minimum code to make the test pass. Nothing more. Resist the urge to be clever yet.
→
🔵 REFACTOR
Clean up — extract, rename, simplify. Tests keep you safe: if they still pass, you haven't broken anything.

↺ back to RED for the next behaviour

Tests written after

  • Confirm existing code
  • Easy to miss edge cases
  • Refactoring feels risky
  • Tests mirror the implementation

Tests written first ✅

  • Define requirements
  • Edge cases become explicit
  • Refactoring is safe
  • Tests mirror the requirements

Unit Tests vs Integration Tests

CONCEPT

Unit test — one class, test doubles

  • All dependencies replaced with Fakes/Stubs/Spies
  • No database, no HTTP, no network
  • Run in: milliseconds
  • Tell you: exactly which class is broken

Unit/ in this project

Application/ImportPessoasUnitTests.cs
Application/GetAllPessoasUnitTests.cs
Domain/RolesTests.cs
Models/TimePeriodUnitTests.cs

Integration test — real stack

  • Real PostgreSQL via Testcontainers
  • Full HTTP stack via WebApplicationFactory
  • Run in: seconds
  • Catch: SQL bugs, EF mappings, HTTP routing, auth

Integration/ in this project

Controllers/PessoasImportControllerTests.cs
UseCases/ImportPessoasIntegrationTests.cs
Infrastructure/PessoaRepositoryIntegrationTests.cs

Rule: start with unit tests. Add integration tests at the boundaries — database, HTTP, external APIs. Most tests should be unit tests.

Test Doubles — Fake, Stub, Spy, Mock

CONCEPT

Replace real dependencies in tests. All four kinds live in this project's TestDoubles/ folder.

Fake — FakePessoaRepository

Working implementation, simpler than the real one. Stores data in memory. Records calls for assertions.

public IReadOnlyList<Pessoa>? LastUpsertedPessoas { get; private set; } public Task<UpsertPessoasResult> UpsertAllAsync(IReadOnlyList<Pessoa> pessoas, CancellationToken ct) { LastUpsertedPessoas = pessoas; // record for assertions return Task.FromResult(new UpsertPessoasResult(pessoas.Count, 0)); }

Stub — StubPessoasDataProvider

Returns canned data you configure. No logic. Use when a dependency needs to return specific data.

// Constructed with the data to return: var stub = new StubPessoasDataProvider([new Pessoa { NII = "22601" }]); // Also records LastRequestedKeys and LastToken

Spy — SpyUnitOfWork

Records how it was called. You assert on the recorded calls in your test body.

public int CommitCalls { get; private set; } public CancellationToken? LastToken { get; private set; } // In your test: uowSpy.CommitCalls.Should().Be(1); uowSpy.LastToken.Should().Be(ct);

Mock — Moq

Spy configured with expectations at runtime. Use for complex setups or call-order verification.

var sequence = new MockSequence(); _repo.InSequence(sequence).Setup(...).ReturnsAsync(keys); _data.InSequence(sequence).Setup(...).ReturnsAsync(pessoas); // Verifies ORDER of calls — not just that they happened

Writing Tests — AAA, Naming, FluentAssertions

CONCEPT

Arrange / Act / Assert

[Fact] public async Task ShouldUpsertSourcePessoasAndCommit_WhenRepositoryHasNoKey() { // Arrange (Given) var ct = new CancellationTokenSource().Token; var fakeRepo = new FakePessoaRepository([]); var keysStub = new StubPessoasImportKeyProvider([new("22601","30001001")]); var dataStub = new StubPessoasDataProvider([new Pessoa { NII = "22601" }]); var uowSpy = new SpyUnitOfWork(); var uut = new ImportPessoas(fakeRepo, dataStub, keysStub, uowSpy); // ^^^ "unit under test" // Act (When) var result = await uut.ExecuteAsync(ct); // Assert (Then) result.TotalProcessed.Should().Be(1); uowSpy.CommitCalls.Should().Be(1); }

TDD Tutorial — Build TimePeriod from Scratch

CONCEPT

Build TimePeriodTdd using strict TDD. Each behaviour starts as a failing test. You'll end up with the same class that already exists — built test-first.

Step 1ShouldSetStartAndEndCorrectly_WhenRangeIsValid — constructor stores start and end
Step 2ShouldAllowEqualStartAndEnd_WhenStartEqualsEnd — passes for free, documents edge case
Step 3ShouldThrow_WhenEndIsBeforeStart — drives the guard clause in the constructor
Step 4ShouldReturnExpectedFormattedString_WhenStartAsStringCalled — drives StartAsString()
Step 5ShouldReturnExpectedFormattedString_WhenEndAsStringCalled — drives EndAsString()
Step 6ShouldKeepFormatting_WhenAsStringMethodsAreCultureIndependent — surfaces subtle culture bug
BonusConvert exception test to [Theory] with 3 InlineData cases (1 day / 1 hour / 1 second before)
Commit rule: one commit per Red → Green transition. test: add step N then feat: implement step N

TDD Tutorial — Steps 1–3

YOUR TURN
💻 Write the test first. See it fail (RED). Then implement minimum code (GREEN).

Step 1 — test first (RED)

[Fact] public void ShouldSetStartAndEndCorrectly_WhenRangeIsValid() { var start = DateTime.Parse("2020-11-24 10:00:00", CultureInfo.InvariantCulture); var end = DateTime.Parse("2020-11-24 12:00:00", CultureInfo.InvariantCulture); var tp = new TimePeriodTdd(start, end); tp.Start.Should().Be(start); tp.End.Should().Be(end); }

Step 1 — minimum implementation (GREEN)

public sealed class TimePeriodTdd { public DateTime Start { get; init; } public DateTime End { get; init; } public TimePeriodTdd(DateTime start, DateTime end) { Start = start; End = end; } }

Step 2 — write test, run — GREEN for free ✅

[Fact] public void ShouldAllowEqualStartAndEnd_WhenStartEqualsEnd() { var ts = DateTime.Parse("2020-11-24 10:00:00", CultureInfo.InvariantCulture); var tp = new TimePeriodTdd(ts, ts); tp.Start.Should().Be(ts); tp.End.Should().Be(ts); } // ← no code change needed. Still valuable as docs.

Step 3 — validation (RED, then add guard)

[Fact] public void ShouldThrow_WhenEndIsBeforeStart() { Action act = () => new TimePeriodTdd( DateTime.Parse("2020-11-25 10:00:00", CultureInfo.InvariantCulture), DateTime.Parse("2020-11-24 10:00:00", CultureInfo.InvariantCulture)); act.Should().Throw<ArgumentException>() .WithMessage("*End timestamp cannot be earlier*"); } // Add to constructor: if (end < start) throw new ArgumentException(...);
